# 地震の時系列地図

気象庁の震源カタログを毎日溜めて、日本の地震を時間に沿って地図に描く。
発生時刻・震央・M・最大震度・深さを、円の大きさと色で表す。時間をさかのぼって再生し、動画に書き出せる。

- 画面：`index.html`（GitHub Pages でそのまま公開）
- 取得：`scripts/fetch.py`。いつ取得するかは `scripts/schedule.py` と `config.json` の `schedule` が決める（GitHub Actions が1時間ごとに起きて、地震情報の一覧だけを見て判断）
  - ふだんは週1回（土曜11時・日本時間）
  - 震度5弱・5強を観測：その地震の発生から14日間、1日1回
  - 震度6弱以上を観測：発生から7日間は6時間ごと、その後14日間は1日1回
  - 観測した直後（前回の取得より後に起きた）は、間隔を待たずにすぐ1回
  - 手で動かせばいつでも（Actions →「気象庁から取得」→ Run workflow）
  - 一覧は直近30日分残り、決まりの期間（最長21日）より長いので、状態は覚えず毎回一覧から判断する。前回の取得の時刻だけ `data/schedule.json`
- データ：`data/events/YYYY/YYYY-MM.csv`（月ごと）と `data/manifest.json`（日ごとの出どころ・件数・捨てた件数と理由・書き換わりの記録）

## データの出どころ（2026-10-11 実測）

| 記号 | 出どころ | 期間 | 遅れ | 中身 |
|---|---|---|---|---|
| C | 震源データ（確定）`eqev/data/bulletin/data/hypo/hYYYY.zip` | 1919〜2023 | 約2年 | 96byte固定長。精度の印・低周波・人工地震の区別・最大震度あり |
| P | 震源リスト（速報）`eqev/data/daily_map/YYYYMMDD.html` | 2024-01-01〜2日前 | 約2日 | 全部の地震。精度の印・震度なし |
| I | 震度データベース `eqdb/data/shindo/api/` | 1919〜2日前 | 約2日 | 揺れを感じた地震。P に最大震度を付けるのに使う |
| Q | 地震情報の一覧 `bosai/quake/data/list.json` | 直近30日 | 数分 | 揺れを感じた地震だけ。座標0.1度、時刻は分まで |

- 日ごとに、いちばん確かな出どころの行だけを持つ（C > P > Q）。弱い出どころで上書きしない
- P と I の突き合わせは、発生時刻（0.1秒）の完全一致と座標の一致だけ。外れた有感地震は捨てずに `I` の行として足し、件数を manifest に残す
  （例：2024-01-01 は有感506件のうち8件が速報の震源リストに無かった）
- 震度データベースが取れなかった日は、震度を「無感」でなく「不明（?）」にする
- 速報（P）を同じ出どころで取り直して中身が変わったら、`manifest.json` の `revisions` に記録する
- 気象庁以外の機関が決めた震源（確定版の U/I 行）、遠地地震、震源の無い発表は入れない。件数と理由を記録する
- **注意**：2016年4月から、確定版に自動処理で決めた震源（印 A/a、年に15〜20万件、ほとんど M1 未満）が加わった。
  M2 以上の年間件数は前後で変わらない（2万4千〜4万）が、M1 以上は2016年をまたぐと増える。年をまたいで回数を比べるなら M2 以上が目安。画面のグラフにも線を引く
- **注意**：速報の震源リストは 2024-01-01 から始まっている。2024年の確定版が出たら速報の2024年分は消えると見込まれるので、自前で溜めている

### CSV の列

`t,lat,lon,dep,mag,maxi,src,q,aux`

- `t` 発生時刻（日本時間）。`2024-01-01T16:10:22.5`、Q は `2024-01-01T16:10`
- `dep` 深さ km（空＝不明）、`mag` M（空＝不明）
- `maxi` 最大震度 `1 2 3 4 5- 5+ 6- 6+ 7`、空＝無感、`?`＝不明（`5 6 F` は1996年9月以前の旧階級）
- `src` 上の表の記号、`q` 確定版の震源決定フラグ（K k A S s a N）、`aux` 確定版の補助情報（1 通常 3 人工 4 噴火 5 低周波）

## 画面

- 時間：つまみ・再生・1コマの刻み（10分〜7日）・速さ（コマ／秒）・期間（既定は直近1年）
- 時刻の状態はひとつ（T）。地図・左上の日付・M-T 図の線・1日の回数の線・動画は、すべて同じ T で描く
- 描く地震：M の下限、最大震度の下限、深さ、低周波地震・精度の低い震源を含めるか。描かない地震は理由ごとに件数を出す
- 見た目：形（円／球）、色の意味（M／深さ／最大震度／経過時間）、大きさの尺度、残る時間（M1 で何日、M が 1 増えるごとに何倍、上限）、波紋
- 大きい円を下に描き、大きいほど中を薄く輪郭を強くする
- 左上に、その日のデータが確定値か速報値かを出す。M-T 図の上端の帯も、灰＝確定・橙＝速報・赤＝発表直後
- 奥行き（形が「円」のとき）：3D の効き（0〜100%）で、深いほど小さく・ぼかし・薄く。M7 以上は薄めない。設定欄は普段は畳んである
- 地図の向き：時計回りに回せる（Leaflet の地図を回転用の枠に入れて枠ごと回し、地震の印は回した後の画面の位置に描く）。回している間、ドラッグは画面の動きを逆に回して渡し、ホイールでの拡大は地図の中心を基準にする
- 断面図：地図の真下に、横＝画面の横方向（回していれば回した後の横方向。両端に方位）、縦＝深さで描く。縦の範囲は「縦横同じ縮尺」か固定（0〜30〜700km）
- グラフ（断面図・M-T 図・回数）は、既定で地図に見えている範囲の地震だけで描く
- 右の操作盤は、地図の右端のつまみで出し入れできる（ブラウザに覚えさせる）
- 表示「期間の合計（集合マーカー）」：期間内の地震を地図の画素の格子でまとめ（拡大・縮小でまとめ直す）、大きさと色＝推定エネルギーの合計を M に置き換えた「M 相当」、数字＝M 相当／回数／エネルギー（J）。エネルギーは グーテンベルク・リヒター(1956) log E = 1.5M + 4.8（J）。断面図も集合マーカーで描く
- 表示「時間に沿って（集合マーカー）」：時刻 T までの「まとめる時間の幅」（直近1日／7日／30日／期間の始めから）の地震を格子でまとめて再生する。発生の瞬間は波紋。累積は前のコマから増えた地震だけを足す。断面図も同じ地震で集合マーカー
- 集合マーカーのまとめ方は k-means（既定）と格子から選ぶ。k-means は地図に見えている範囲の地震を、静止画（期間の合計）では震源の東西・南北・深さの3次元、時間に沿った再生では時間も加えた4次元で k 個にまとめる。距離は km（東経137度中心の正弦図法）、深さは重み付き、時間は「1日を何 km とみなすか」。種を固定した k-means++ で、同じ条件なら同じ結果。マーカーは塊の中心にいちばん近い実際の震央（地震の無い場所に出さない）。再生中はその時刻までに起きた地震だけで位置と大きさを決め、まだ起きていない地震の情報は出さない（塊の分け方そのものは期間全体を見て決めた「振り返り」）。中心を求めるのに使う地震は最大2万件（等間隔に間引き）、割り当ては全部
  - マーカーの数は 10 段階（段階1で10個、1段ごとに 10^(1/9) 倍、段階10で100個）。大きさは M 相当が 1 上がるごとに一定の倍率（既定 1.35 倍）
  - k-means は地図を動かし終えたときと設定を変えたときに 1 回だけ計算し、段階ごとに結果を取っておく（再生中・動画では計算しない。1コマ約2ミリ秒）
  - 計算は画面とは別の計算場所（Web Worker、`js/kmworker.js`）で行うので、計算中も地図のパン・ピンチやつまみは止まらない。地図を続けて動かしている間はまとめ直さず、手が止まって 0.4 秒たってから始める。答えが届くまでは前の塊を描き、地図の上に「まとめ直しています」と出す（地震の選び方・期間が変わったときは、前の塊は描かない）。動画の書き出し中だけは画面の側で計算する。計算の中身は `QC.kmSolve`（`js/core.js`）で、画面の側で計算したときと同じ答えになることを検査で確かめている
  - 再生（xyzt）では k を「同時に見えるマーカーの数」とする。塊は時期でも分かれるので、全体の塊の数を「期間を km にした長さ ÷ 塊 1 つ分の広さの一辺」倍から始め、期間内 9 時刻で実際に見える数を数えて、k の ±15% を外れたら外れた割合だけ塊の数を変えて 1 回だけまとめ直す（上限 600）。
    実測（2024年1年・全国・1日3km）：以前は全体40塊で同時に見えるのは14、いまは全体237塊で同時に約57
- 格子のときの細かさ（格子の大きさ）は「時間」の欄のつまみで変えられる
- 断面図は右上のボタンで 小・中・大・隠す（隠したあとは帯を押すと戻る）
- 再生の最後のまとめ：期間の最後まで再生すると、集合マーカーを数秒出したあと、窓全体を暗くして統計（回数・最大の地震・震度の回数・最も多かった日・エネルギーの合計・深さの割合・M ごとの回数の棒グラフ）を出す。押すか Esc で閉じる
- 低周波地震だけを描ける（印のある確定版＝2023年まで。速報は区別できないので描かず、件数を出す。切り替えると M の下限を −2 にする）
- 重ねる図：想定震源域（長期評価）を海域ごとに選んで重ねる（千島海溝・日本海溝・相模トラフ・南海トラフ・日向灘・与那国島周辺・日本海東縁部）。J-SHIS（防災科研）の震源断層 Y2024 AVR（21 の符号）を `research/build_source_areas.py` で加工し `data/overlays/source_areas.json` に置く。
  主な想定（南海トラフ・千島海溝 17世紀型・日本海溝 東北沖型・相模トラフ・日向灘・与那国）は震源域に入る割合（1・25・50・75%以上）の濃淡、どの想定も外形の線（点線＝長方形の断層面）と名前、プレート境界（断層面）の等深線（10km ごと）。
  J-SHIS の規約で元のデータのそのままの複製・形式変換の配布は禁止なので、元のデータはリポジトリに置かない（符号の一覧は J-SHIS の断層コード規約 A-RULES.pdf の表2-2・2-3、今のモデルで使える符号は fltsearch API で確かめた）。
  加工の確かめ（`research/check_source_areas.py`）：元の点（長方形は面の内側の 9 点）は全部の符号で 99.9〜100% が外形の内側、深さの格子からのはみ出しは中央値 0〜2.3km（点の集まりは 0.2〜0.4km）。
  長方形が何通りも重なる所（与那国島周辺・日本海東縁部）は場所ごとの深さが 1 つに決まらないので、深さを「いちばん浅い〜深い」の幅で持ち、等深線は幅 5km 以内の所だけ引く。固着の観測値ではない（観測による固着の数値は公開物が見つからない）
- 色「想定震源域からの距離」：震源から想定震源域の面（各升の深さの幅）までの立体の距離（5・10・20・40・80・150km で色分け、150km 以上は灰、深さ不明は白の点線）。対象は重ねる図で選んだ海域（選んでいなければ全部）。吹き出しに、いちばん近い海域と距離、面より浅いか深いかを出す。0.05 度の格子で求めるので、横に約 2.5km までの誤差がある。1 年分（13.6 万回）で約 0.5 秒（色を切り替えたとき・絞り込みを変えたときに 1 回）
- 設定は URL の `#` 以降に残るので、そのまま共有できる
- 動画：いま見えている範囲（回していれば回したまま）で、期間の最初から最後まで1コマずつ描いて MP4（対応していなければ WebM）で保存する。日付・凡例・出典・北の向き・断面図・M-T 図を焼き込む。書き出しを始めると操作盤を引っ込め（終わると戻す）、最後に集合マーカーと統計のまとめを付ける

### 立体表示（試作）

地図の右上の「3D」（または操作盤の「立体で見る」）→ 地図の上をドラッグして範囲を囲む（または「今見えている範囲全部」）→ 確かめて「この範囲を立体で見る」。
選んだ範囲の地震だけを、半透明の地面（地理院タイル、範囲で切り取り）の下に、実際の深さの位置に描く。表示モードと再生は平面の地図と同じ：

- 時間に沿って（1 つずつ）：その時刻に残っている地震を震源の立体位置に。大きさ・色・薄れ方・波紋は平面と同じ決まり
- 期間の合計（集合マーカー）：選んだ範囲の地震を k-means（xyz）でまとめ、立体の模型のように
- 時間に沿って（集合マーカー）：k-means（xyzt）でまとめ、その時刻の姿で（立体ではいつも k-means）

作りの決まり：
- 回す・傾ける・拡大するのは画面への写し方だけで、計算はし直さない。k-means は「選んだ範囲」でまとめる（画面に見えている範囲ではない）ので、回しても同じ塊。大きさは地面の上の長さ（m）で持ち、立体にした直後の見かけが平面の地図と同じになるようにしてある（近づけば大きく見える）
- 深さの強調（×1〜×10、既定は「自動」＝箱の深さが範囲の短い辺の約3分の1になる倍率）は位置の写し方だけを変える
- 地形・海底地形：AWS Terrain Tiles（Terrarium 形式。日本の周りの海底は ETOPO1〈NOAA〉、陸は SRTM・GMTED〈USGS〉。2026-10-13 に三陸沖のタイルで最深 7,666m を確かめた）に地理院タイルを貼る。高さは震源と同じ倍率で強調する（地形だけ強めると、海底の下の地震が海底より上に見えてしまうため）。地形どうしは前後を正しく重ね、震源・箱は地形の後に前後を見ずに重ねる（地面の下が透けて見える）。切り替えで平らな地面にもできる
- 想定震源域（重ねる図で選んだ海域）は、外形と等深線を実際の深さに描く
- 平面の地図の断面図と奥行きの効き（小さく・ぼかし・かすみ）は使わない
- 深さ不明の地震は立体の位置が決まらないので描かず、数を出す。地表の影（震央）と、M4 以上の震央から震源への線を出せる
- 下のグラフ（「地図に見えている範囲の地震だけで描く」のとき）は、立体表示に選んだ範囲の地震で描く
- 地図を回しているときに選んだ範囲は、画面の四角を囲む南北・東西の四角になる（選んだあと地図の上に点線で見せる）
- 回す：ドラッグの左右＝縦の軸（z）まわり、上下＝傾き（x 軸まわり、真上 0°〜ほぼ真横 85°。地面の下から見上げることはできない）。Shift＋ドラッグ・右ドラッグで移動、ホイール・ピンチで拡大、2本指で回す。「回し続ける」は 30 秒で 1 周
- 回転の中心：画面の中心の真下の、箱の深さの真ん中（deck.gl の見え方の position で中心の高さを下げている）。地面の上の点を中心にすると、地面の下の箱が大きく振れて見失うため。移動すると中心も一緒に動く。どの倍率・傾きでも中心の画面の位置が動かないことを確かめた
- 「凡例などを隠す」（または H キー）：凡例と立体の操作盤を隠す（時刻は隠さない）。平面の地図でも凡例を隠せる
- 描画は deck.gl 9.3.11（MIT、`vendor/deckgl-9.3.11.min.js`、npm の配布物の SHA-512 を確かめて同梱）。初めて立体表示を開いたときに読み込む
- 実測（東北〜関東、7万回）：k-means xyz 0.4 秒・xyzt 1.3 秒（別の計算場所）、再生 1 コマ約 11 ミリ秒（下のグラフを含む）、回している間に長いタスクなし
- まだ無いもの：動画の書き出し（立体表示の間は押せない）

### 球（推定の揺れの範囲）

形を「球」にすると、震源を中心に「推定震度が境目（震度3〜6弱から選ぶ）になる距離」を半径とする球を描く。
外の輪＝球（深いほど薄く）、塗り＝球が地表に出る円（推定で境目以上の範囲）、点＝震央。

- 推定は 司・翠川(1999) の最大速度の距離減衰式と 翠川ほか(1999) の計測震度への換算（I = 2.68 + 1.72 log PGV）。点震源として震源距離を使う
- 式は距離100kmまでを対象に作られたもの。地盤・断層の広がり・異常震域は考えない
- 式には「深い地震ほど同じ距離でも強く揺れる」項（+0.0038×深さ）があり、大きな地震では深いほど地表の円が大きくなることがある
- 観測点ごとの震度との突き合わせ：`research/sphere_check.py`（取得）と `research/sphere_variants.py`（条件を変えた比較）

## 取得を手で動かす

GitHub の Actions →「気象庁から取得」→ Run workflow。種類の欄に：

- `update`：いつもの取得（直近の一覧＋直近10日の速報）
- `catalog 2011 2019`：確定版を年の範囲で足す（過去の地震を足すとき）
- `daily 2024-01-01 2024-01-31`：速報を日の範囲で取り直す

手元なら `python3 scripts/fetch.py update` など。気象庁へは1秒に1回までにしている（`config.json`）。

## 検査

```bash
python3 -m unittest tests.test_jma
```

```bash
TZ=America/New_York node tests/core.test.js
```

```bash
python3 tests/mutate.py
```

`mutate.py` は破壊試験。実装を1か所ずつ壊した写しで検査を動かし、毎回落ちることを確かめる（40通り）。
画面の計算は端末をニューヨーク時間にして試す（日本時間の端末では時刻の壊れ方が見えないことがある）。
